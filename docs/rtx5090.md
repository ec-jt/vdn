### Paper BF16 switches and rollback

The [benchmark wrapper](../scripts/benchmark_rtx5090_nsight.sh) accepts a fifth,
independent profile argument: baseline, vda_fused, vda_overlap or vda_both.
Omission preserves the baseline. The combined profile exists for research but
was not full-trajectory tested and is not recommended. Use fresh labels:

```bash
# Recommended measured route, with both new experiments disabled:
bash scripts/benchmark_rtx5090_nsight.sh UNIQUE_SAFE_LABEL plain allgather next_block baseline
# Reproduce the REJECTED arithmetic candidate, not a quality-safe fast profile:
bash scripts/benchmark_rtx5090_nsight.sh UNIQUE_FUSED_LABEL plain allgather next_block vda_fused
# Exact in this tested trajectory, but no demonstrated speed benefit:
bash scripts/benchmark_rtx5090_nsight.sh UNIQUE_OVERLAP_LABEL plain allgather next_block vda_overlap
```

The default-off switches are defined in [configuration](../src/config/inference.py:42).
Global inference kernels and FP8 remain disabled; enabling all kernels is not a
substitute for either narrow experiment. Roll back by selecting baseline or
omitting the fifth argument. Existing route/prefetch defaults are unchanged.

This pass implemented fused boundary gather plus a BF16-rounding-preserving
epilogue, and separate rank-local VDA/softmax stream concurrency. The
[kernel report](../artifacts/rtx5090/paper-bf16-20261005/kernel-HANDOFF.md) records
operator FP64 oracles and the slower statistics fusion that was excluded.
The [stream report](../artifacts/rtx5090/paper-bf16-20261005/overlap-HANDOFF.md)
records exactness, allocator lifetime, cold compilation and exception tests.
Chunk-boundary scans remain deferred pending text-state, anchor, injection and

No decoder arithmetic changed: actual video decode stayed 4.241-4.287 seconds.

## Eight-GPU status: experimental denoiser, exact tested decoder parity

The [final post-fix verification](../artifacts/rtx5090/8gpu-FINAL-DETERMINISTIC.md)
records **124 frames: 131.363 s denoise / 292.160 s whole process** and
**345 frames: 292.874 s / 468.550 s**, with denoise/whole speedups **1.282x /
1.005x** and **1.380x / 1.206x** against historical CPU offload. The 1.410 s
whole-process saving at 124 is not a statistically established improvement.
Both media and finite-latent checks pass; **130 CUDA-enabled tests pass, no skips**.
Final baseline video/audio relative L2 is **0.359819 / 0.082718** at 124 and
**0.226952 / 0.091432** at 345. All ranks perform attention and decoder work.
Maximum denoise allocated/reserved peaks are **13.194 / 14.014 GiB** and
**17.064 / 20.689 GiB**; sampled whole-device maxima are **15,322 / 25,732 MiB**.

The [production report](../artifacts/rtx5090/8gpu-PRODUCTION.md) separates measured
performance from **material denoiser drift**. The
[bounded drift investigation](../artifacts/rtx5090/8gpu-DRIFT-ROOT-CAUSE.md) fixed
two avoidable issues: temporal-conv helper selection and nondeterministic frame
sums. Repeated post-fix 124-frame denoise latents match bitwise, but their baseline
video/audio relative L2 remains approximately **0.360 / 0.083**. Operator probes
are consistent with BF16 reduction/kernel rounding; global cause and quality
equivalence are **not proven**. Summary norms/checksums do not prove all-tensor
equality; matching checkpoint header hashes do not prove all-weight payload identity.

The unchanged distributed decoder separately achieved **exact raw-float and RGB
parity on identical saved baseline latents at both lengths**, as recorded in the
[decoder report](../artifacts/rtx5090/DISTRIBUTED_DECODER.md). That evidence does
not make the experimental denoiser numerically interchangeable with baseline.
FSDP-style weight gathers and attention exchanges remain PCIe bottlenecks.
Rank-zero full CPU assembly is not strict bounded startup.

### Exact checkpoint, scheduler, CFG, and adapter distinctions

- **Checkpoint:** original 8NFE launchers select the Stage-DMD step-250 artifact;
  original 50NFE launchers select Stage-B step-2000. The local overlays point to
  the corresponding existing [Stage-DMD](../../models/OpenVDN/vdn-minimax-h3/stage-dmd-step-250/)
  and [Stage-B](../../models/OpenVDN/vdn-minimax-h3/stage-b-step-2000/) directories,
  with the same [H3 base](../../models/OpenVDN/vdn-minimax-h3/h3-base/).
- **Scheduler:** the shared [sampler](../src/inference/render.py:93) creates
  separate MiniMax H3 video/audio schedulers with shifts **12.0 / 3.0** for both
  families. It requests **9 / 51 sigma grid points**, including terminal zero,
  yielding **8 / 50 actual model evaluations** respectively. The sampler and
  scheduler class do not change between families; the checkpoint and grid length
  do. Seed defaults to 42. FP8 presets, including both Ulysses variants, perform
  a separate discarded two-evaluation warmup, not two extra production steps
  ([single-GPU warmup](../src/inference/infer.py:58),
  [distributed warmup](../src/inference/infer_ulysses.py:102)).
- **CFG:** neither family adds classifier-free guidance at runtime. The
  [denoising loop](../src/inference/render.py:124) makes one conditional forward
  and directly updates video/audio latents. There is no unconditional/negative
  prediction or guidance combination. In particular, 50NFE does not mean 100
  conditional/unconditional evaluations, and 8NFE does not introduce a CFG toggle.
- **Adapters:** CPU-only inspection of the local safetensors JSON headers
  confirmed **416 default-adapter tensors (208 A/B pairs), no turbo tensors** in
  Stage-B, and **416 default plus 726 turbo tensors (208 + 363 A/B pairs)** in
  Stage-DMD. Both also contain 800 branch tensors. Header inspection read no
  tensor payloads and proves presence, not numerical parity. Stage-B is therefore
  **not adapter-free**. [Assembly](../src/inference/utils/assemble.py:135) loads
  artifact branch weights and merges the artifact's adapters via the
  [LoRA merger](../src/inference/utils/lora.py:1), default before turbo, then any
  external adapters, before compute tuning/FP8. None of these original launchers
  requests an external adapter. The DMD/turbo distinction is checkpoint content,
  not a runtime adapter switch or merely changing the number of steps.

### Compute variants are not automatically portable optimizations

The tuned switch enables fused QK normalization/RoPE, normalization/AdaLN/residual
and SwiGLU operations, and optimized softmax/linear-attention bodies including
temporal convolution, frame statistics, and VDN scan kernels. See the
[kernel inventory](../src/config/inference.py:21) and
[installation](../src/models/hybrid_transform.py:73). Single-GPU originals select
automatic softmax: on CUDA it resolves to decomposed, but the
[execution selector](../src/models/hybrid_attention.py:155) requires inference
kernels for that path, so untuned window attention still uses Flex. H200 Ulysses
explicitly selects Flex; B200 explicitly selects decomposed softmax.

[FP8 conversion](../src/models/ops/fp8_linear.py:298) targets E4M3 linear layers
only when both widths are at least 4096; every shipped FP8 preset skips zero end
blocks. Narrow gates/beta/AdaLN projections remain excluded by width, with FP32
islands retained. It is not whole-model FP8. The
[architecture dispatch](../src/models/ops/fp8_linear.py:141) uses rowwise
activation/per-output-channel weight scales on SM90 and per-tensor scales for
capability major 10 or greater. SM120 entering that latter branch is **not proof
of RTX 5090 correctness, performance, or memory fit**. Tuned and FP8 paths need
SM120 kernel/numerical parity checks and measured resident/activation/workspace
fit before support claims; FP8 can change the generated trajectory. The current
CPU-offload policy explicitly rejects both tuning and FP8, so simply enabling
their flags in the baseline overlay is not a supported route.

Both H200/B200 Ulysses variants use **sequence parallelism with replicated model
weights**, not eight-way weight sharding. [Each rank builds the full transformer](../src/inference/infer_ulysses.py:54),
then [Ulysses](../src/inference/utils/ulysses.py:12) partitions sequence rows and
redistributes attention work with all-to-all; only rank zero loads decoders.
Eight 32 GB cards do not become one pooled weight store. Their rank split and
interconnect assumptions require separate 5090 validation; the baseline's
single-process offload cannot simply be combined with this path.

**Historical remaining scope at the inventory milestone:** eight-GPU weight
distribution was then unimplemented. It is now implemented and production-measured
as documented above, with numerical and performance limits. Real new-prompt encoding is blocked by missing
encoder weights, independently of cached-prompt rendering. The optional one-shot
encoder must finish and exit before rendering, not reserve a permanent encoder
GPU. The fast-first milestone is fulfilled, but it does **not** complete the
global request for all variants, full new-prompt operation, and optimized
eight-GPU execution. This inventory adds documentation only, not support or
measurements for the unvalidated paths.

## Memory policy and the demonstrated OOM fix

The [strict CPU loader](../src/inference/utils/cpu_loading.py) verifies keys,
shapes, shard assignments, and CPU materialization, rejecting embedded
quantization and device-map dispatch. [Assembly](../src/inference/utils/assemble.py)
applies the hybrid transform, loads branch weights, merges checkpoint/default,
turbo, then external adapters, and casts on CPU. There is no initial whole-model
CUDA move.

The [offload controller](../src/inference/utils/block_offload.py) keeps immutable
CPU backing and groups complete H3 transformer blocks, including children whose
weights are accessed directly. A root group holds endpoints, the whole text
refiner, and remaining buffers during each forward. Weight residency is one block
plus that root group. Restoring CPU storage avoids copying immutable weights back
from CUDA. There is no prefetch, overlap stream, pinning, or disk offload.

This bounds **weights, not activations or workspaces**. The first 345-frame
attempt failed in eager linear-statistics preparation while allocating 1.35 GiB,
with allocator peaks of 28.850 GiB allocated and 30.551 GiB reserved. Its
[failure log](../artifacts/rtx5090/render-345-attempt1.log) and
[original journal](../artifacts/rtx5090/render-345-attempt1.metrics.jsonl) are preserved.
The targeted correction in [`_frame_statistics()`](../src/models/linear_attention/scan.py:121)
uses the existing 16-frame statistics batching for no-gradient eager evaluation,
instead of materializing operands for all 100 interior frames together. It keeps
the eager arithmetic and does not enable fused kernels or TF32. Gradient-enabled
training retains its original single pass. The original 124-frame measurement
predates this correction and is preserved separately from the final-code rerun above.

The [second attempt](../artifacts/rtx5090/render-345-attempt2.log) passed statistics
but failed at readout normalization. The eager branch retained features and scan
banks beyond their last use. [Readout cleanup](../src/models/linear_attention/branch.py:354)
now releases those dead local references before normalization; operation order and
arithmetic are unchanged, and autograd independently retains tensors needed for
backward. Both fixes address observed allocations, not speculative kernel changes.

[Sequential decoding](../src/inference/render.py:188) releases denoiser weights,
decodes video with the installed VAE's existing tiling/chunking, transfers frames
to CPU, evicts the video VAE, then decodes audio and evicts its VAE. Cleanup runs
on failure. The full video output still exists before its CPU transfer. The
legacy policy retains simultaneous decoder placement.

The offload policy is inference-only, serial, and single-process. Do not mutate,
cast, move, train, compile, or concurrently call the model after installing hooks.
Validation rejects FP8, non-BF16 precision, optimized inference kernels, teacher
mode, distributed/Ulysses operation, and incompatible existing hooks. It depends
on the pinned Diffusers internal APIs. CPU RAM must hold weights, assembly
transients, and offload backing; synchronous PCIe transfers add latency.

## Distant linear attention is exercised

Frame count alone is not the proof. The installed H3 mapping is output frames
N = 17n + 5 to latent frames F = 5n + 2. The checkpoint uses five-frame chunks,
window radius one, both endpoint anchors, and text state. Spatially, 768 x 1344
becomes 48 x 84 VAE cells and then 24 x 42 = 1,008 tokens per latent frame.

| Layout | 124 frames | 345 frames |
| --- | ---: | ---: |
| Latent frames | 37 | 102 |
| Five-frame chunks (last has two frames) | 8 | 21 |
| Generated video tokens | 37,296 | 102,816 |
| Interior scan frames, excluding endpoint anchors | 35 | 100 |
| Interior scan tokens | 35,280 | 100,800 |

For frame t in chunk c = floor(t/5), the inclusive local window is
[5c - 5, 5c + 9], clipped to the clip. Endpoint anchors stay in dense softmax and
are excluded from the linear scan. At t = 15 the local window is [10, 24], so
distant video is prefix [1, 9] plus suffix [25, 35] for 124 frames, or [25, 100]
for 345. Both are nonempty in both workloads. Neither the full-window bypass nor
the anchor-only early return applies. Thus the successful 124-frame render already
executes distant scans/readout; the failed first 345 attempt proves branch entry
only. See [layout validation](../src/models/sequence_layout.py:62),
[window geometry](../src/models/softmax_attention/window.py:26),
[branch dispatch](../src/models/hybrid_attention.py:178), and
[anchor pruning](../src/models/linear_attention/branch.py:301).

## Measurement interpretation

- **Cached denoise:** only the evaluation loop, using previously encoded conditioning.
- **Cached-prompt render process:** startup, CPU assembly, cache loading, denoise,
  optional latent save, sequential decode, media encoding, and record writing.
- **Full prompt-to-video:** additionally includes encoder load, encoding, cache save,
  and encoder teardown. This was not measured because real encoder weights are absent.

The printed denoise total sums per-evaluation wall times. The enclosing phase also
includes preparation/unpacking, and phase instrumentation adds overhead. The first
step is cold and may include compilation; later steps may recompile. **Compilation
time was not isolated.** Zero warmup does not imply empty on-disk compiler caches.

The [phase journal](../src/inference/utils/metrics.py) reports synchronized wall
time, Torch allocated/reserved current and peak bytes, and boundary CPU RSS.
Allocated and reserved peaks are distinct allocator measurements, not total device
usage or just weights. Use phase-end events: phase-start peaks are sampled before
the reset and can describe the preceding interval. Nested phase peaks retain child
maxima; do not add child and parent durations. RSS peaks are process-lifetime high
water marks, not phase-local peaks. GNU time supplies separate whole-process wall
time and peak RSS. Binary GiB means bytes divided by 2^30.

These measurements do not validate quality, arbitrary prompts/resolutions, a
distributed RTX 5090 path, or B200 performance. The repository's B200 denoise
benchmarks have different hardware, precision, warmup, and timing boundaries and
must not be relabeled or extrapolated to this path.

**Real new-prompt encoding remains untested: the local Qwen3VL weights are missing.**

The [encoder launcher](../scripts/inference/encode_prompt_rtx5090.sh) requires

```bash

ENCODER_GPU=0 \

  --prompt 'Your exact prompt text' --out /new/cache/my_prompt.pt
```

Run the encoder separately and wait for exit before rendering. It forces local-only
loading and whole-layer CPU offload, refuses existing output caches, and exits after
saving CPU tensors. It does not detect a busy GPU. No GPU is permanently reserved
for encoding, and no seven-plus-one GPU partition is required.

The [encoder implementation](../src/inference/encode_prompt.py) preserves verbatim
text (no chat template or extra special tokens), hidden state 50, BF16 embeddings
of shape (L, 5120), and integer text tags equal to one. The generic CLI retains
its legacy Hub fallback and whole-model placement unless the explicit local/offload
options are selected. Do not use that whole-model CUDA path for the approximately
62 GB conditioner on a 5090.

Accelerate stages complete text decoder layers; embeddings and other leaves are
independently offloaded. Unused vision weights and output head stay CPU-backed;
small rotary buffers can remain on CUDA until exit. The CPU state mapping is passed
explicitly to avoid the installed dispatcher's empty-root extraction edge case.
No automatic placement, quantization, disk offload, or permanent service is used.
The default 1,024-token limit rejects rather than truncates longer inputs. Memory
must also accommodate activations and all requested hidden states; real encoder
RAM/VRAM fit and numerical parity are not established.

### Opt-in exact all-gather attention transport (124-frame validation)

The standard Ulysses runtime accepts allgather as an opt-in attention exchange.
It gathers padded sequence shards for input and head shards for output, then
copies only the local result into independent contiguous storage. It does not
change denoiser precision, masks, scheduler, arithmetic, head ordering, or decoder
math. Branch-parallel mode is not supported. Generic defaults remain alltoall;
the selected eight-5090 transport launcher and benchmark default remain broadcast.

Use fresh labels and exclusive ownership of all eight idle GPUs. The fixed
[benchmark launcher](../scripts/benchmark_rtx5090_nsight.sh) guards output names,
keeps startup shard distribution on broadcast, fixes 124 frames / 8 NFE / seed 42 /
prompt 0 / BF16 / Flex / FP8 off, and supervises descendants with a 900-second
deadline. Nsight Systems 2025.5.2 is installed and CUDA 13 / SM120 capture works;
no installation is needed.

```bash
# Opt-in candidate, baseline rollback, and per-worker all-rank capture:
bash scripts/benchmark_rtx5090_nsight.sh UNIQUE_AG_LABEL plain allgather
bash scripts/benchmark_rtx5090_nsight.sh UNIQUE_BC_LABEL plain broadcast
```

### Opt-in next-block weight prefetch (124-frame validation)

The [bounded experiment](../artifacts/rtx5090/prefetch-20261005T0912Z/FINAL.md)

projection/FFN tail, not attention traffic. Forward/error/release paths drain owned
